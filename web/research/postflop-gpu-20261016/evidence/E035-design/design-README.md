# E035 prospective exact-positive-zero fold shortcut

Source preparation only. The integer predicate is fused into the existing shared reach load and its first barrier. It rejects negative zero, every nonzero finite value and every nonfinite bit pattern. The finite-payout shortcut writes each logical output as amount*positive-zero, retaining negative-zero outputs where required. All fallback arithmetic and ordering remain unchanged.

One focused GPU unit will compare the complete actual candidate fold kernel with a pinned old fold-only GPU reference at the same128-thread shape. Twelve named cases for both players plus two count0 cases cover the exact predicate, signed payouts, overflow/nonfinite fallbacks, partial input/output lanes, guard preservation and immutable inputs. No production branch counters or alternate launch shapes are introduced.

D066 incidence is not measured cost or a speed bound. Compilation, native tests, activation and primary execution need separate root authorization; this design authorizes none of them.
