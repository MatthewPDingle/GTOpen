# D053 independent source challenge: actor-1 down-to-up sigma cache

**Source-feasible, with explicit integration conditions; no measured usefulness or immediate implementation approval.** The earlier deferral remains intact. Actor-1-only caching is distinct from D038's within-up register reuse and from the preflop sigma-arena removal. No source-level lifetime contradiction was found. A fixed complete-cycle experiment could falsify the idea if root chooses to authorize it; source inspection does not establish 2% headroom or a resource threshold.

References below use accepted E020 files, hash-verified against its immutable 162-entry binary manifest. Five possibly changing repository paths were read from `runs/E027-design/base`; continuation/arena files were verified unchanged. This review does not inspect or endorse the active E027 candidate.

## What it saves, and what remains

`kernels.cu:73–91` already computes normalized actor-1 probabilities in down. `:373–396` recomputes the positive-part regret sum and probabilities in up1. A cache can remove that up-side normalization, but old regrets are still needed for `r>0 ? pos : neg` and `r*d + (val-out)`. Preserve the child accumulation order and update expressions. D038 documents that common NA2/3/4 up code already reuses normalized registers between value and strategy updates: two textual sigma expressions are not evidence of two hardware divisions. New sigma loads/writes, possible changed register live ranges and allocation/init cost offset the source arithmetic savings; compiled and complete-cycle effects remain unknown.

Allocate `4*A1` bytes for the finalized player-1 action arena, not both players. The retained rainbow full-layout anchor has A1=185,172,163, hence 740,688,652 bytes. This is a payload calculation, not new measured device allocation; compact layouts differ. At least a write and subsequent read of each consumed sigma word are introduced. No selected D045 interval or old preflop result establishes a whole-solve timing fraction or performance bound.

## Exactness and lifetime conditions

- Preserve down's uniform child reach **pr/na** (`kernels.cu:81,89`). Cache **1/na** separately, as up uses (`:379`). Do not replace division with `pr*(1/na)`, recover sigma from reach ratios, change the positive-part ternary/ascending +0 sum/1e-12 threshold, or skip cache production for zero own reach: up can still update regrets there. Keep original lock branches; locked slots may remain unwritten only because up bypasses them.
- Full first p0 down produces cache1. Up0 writes only regrets0/strategy0 (`mod.rs:975–976`); E015 second down has nh1=0 (`:763–820`) and must leave cache1 intact. Up1 consumes it. No cross-iteration validity flag or extra graph variant is inherently needed. Every subsequent pair begins with a full producer.
- Allocate the cache before capture and keep its pointer stable. Eager/profiled/captured pairs (`mod.rs:393–449`) must have the same producer-consumer ordering. Warm resumed solvers can capture immediately; capture itself must not be mistaken for a completed producer execution. Queue g0 before g1 on the same stream as today.
- Evaluation down uses strategy sums (`mod.rs:545–589`), so do not consume its probabilities as regret sigma. Prefer disabling cache writes for evaluation; if writes are allowed, the next training producer must completely overwrite all consumed slots. Existing evaluation-up stays unchanged. Lock-table replacement invalidates graphs (`:1046–1057`); unlocked nodes must be freshly produced next time. Errors must never resume at an isolated cached up/second graph.
- Standalone continuation `sweep(p)` always performs full down (`mod.rs:178–194,757–760`), even p1 and arbitrary order. Root uploads, restored regrets and projection/transport therefore precede fresh production. No sigma serialization, projection or canonical transport is needed; it is transient scratch, not retained learning state.

## Integration traps and smallest useful validation

Index cache1 with the finalized GPU `node_data_off` and true nh1 (`plan.rs:358–393`; `arena.rs:37–63`), after full-versus-compact selection (`mod.rs:208–220`). In stored continuation the active GPU traversal is full while the parked `StoragePlan` is compact (`continuation_storage.rs:164–190,314–345`): parked offsets/lengths are the wrong cache oracle. Inactive/sentinel and locked slots must not be read.

Paging/stored currently share seven mutable buffers (`continuation_paging.rs:10–55`; `continuation_storage.rs:93–139`). A cache left resident in each board silently defeats that memory design. Either make it an eighth borrowed scratch buffer with matching take/swap/absorb/length/poison accounting, or explicitly disable it in those constructors with accounted allocation/dispatch. Scratch contents need not be uploaded/downloaded or persisted. Admission must include 4*A1 in both full-F32 eligibility and final compact/full cost, public estimates and planned/observed continuation payload (`mod.rs:213–220`; `game.rs:419–421`; `continuation_capacity.rs:27–81`). Workspace capacity can exceed one board's length; actual traversal offsets, not another board's maximum, determine valid accesses.

Keep the registered three-fixture complete-cycle primary and its unchanged 18-result/138-check, 2% and fixture-regression gates. No new timing harness or arbitrary register/occupancy gate is required. Before acceptance, the smallest additional numerical control is a small immutable-E020 versus candidate raw-device comparison of a full pair plus standalone p1: seeded nonuniform/negative/all-zero/near-threshold regrets, zero reach, NA2/3/4 and one generic NA9, both DCFR/CFR+, compressed and F32/full versus compact. Compare logical raw regrets/strategy/reach and root CFVs before compression; explicitly poison cache and locked/inactive guards. Exercise warm first-capture, graph/profile switching, cached evaluation between pairs, lock/unlock and repeated p1 with changed roots. Existing original state/menu/resume/F32/GPU controls remain necessary. If the cache participates in paging/storage, add two-board workspace swaps, projection/restoration and exact/tight-budget planned-versus-observed payload checks. If opted out there, verify that no per-board cache allocation or cached dispatch occurs. Primary fingerprints alone are insufficient for this new scratch lifetime.
