# D041 additive narrower U16 proof

Root proposed a smaller alternative to parallelizing every zero check. This is source-feasible but **not yet a performance candidate**: measure the U16 q-scan fraction first. All original D041 files remain unchanged; no code, compiler, native diagnostic or GPU work was performed.

Actual Store::read_f32 routes U16 to decode_u16 (`store.rs:134-135,161-166`): `k=scale/65535.0`, then `out=q as f32*k`. Every u16 value0..65535 converts exactly to finite nonnegative f32. If scale.to_bits()==0, k is+0 and every output is+0, regardless of the q word. This permits removing only the U16 q OR condition from can_upload_zeros while keeping its exact scale-bit and inactive-snapshot conditions. It does not justify removing the I16 test: a negative signed q with scale+0 decodes to-0. F32 remains unchanged; -0/nonzero/nonfinite scales remain rejected. No float reassociation or precision change is involved.

The scope is only construction of the same decoded GPU image. **Do not clear/canonicalize host q or scales.** `cfr.rs:710-751` solved_strategy_into normalizes U16 q directly while ignoring scale, so arbitrary nonzero q/+0scale is not globally interchangeable with rawzero host storage. Existing upload already decodes it to+0; the proposed shortcut must leave CPU queries and saved input state untouched before the existing sync. Existing full write_arena and compact active/inactive readback paths then re-encode+0 as before. Compact fallback already represents decoded inactive+0 by its usize::MAX sentinel. The initial[which].is_empty()/inactive sentinel guards must remain, including unusual reused layouts.

Future proof, if timing warrants: compare all65536 actual Rust decode_u16 outputs for scale+0, retain signed/nonfinite/bad-scale/F32/snapshot rejection coverage, and split the current mixed signed/unsigned rejection test narrowly so U16 nonzero q/+0 is tested against decoded bits. A native nonzero-q/+0scale full/compact control should preserve hostq/query/save observations before the first existing sync, then compare complete raw stores after sync and CPU materialization against the original upload path. Do not delete the existing negative-I16 case or infer equivalence only from compressed fingerprints. Independent source criticism found no blocker with these restrictions; this is not executed proof.
