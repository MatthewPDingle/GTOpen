## Correction to sealed D030 and E018 construction constraint

D030's shorthand `child_cfv_slots[e] = plan.cfv_slot[tree.children[e]]` is unsafe for the entire vector: `tree.rs:10` defines SENTINEL=u32::MAX, and chance constructors initialize 52-entry arrays with it (`tree.rs:730,773`). Blind indexing would panic. Leave D030 sealed; this review corrects the shorthand.

Either preserve sentinel entries explicitly before indexing valid children, or initialize a full-length sentinel vector and fill only positions consumed by visited action nodes. Every live action edge must map to the same physical `cfv_slot`, in unchanged child order, and be less than `cfv_blocks`. Inactive/unvisited entries may retain sentinel but must never be consumed. `plan.rs:214–241` physical scratch-slot reuse remains unchanged. Full-arena conversion changes data offsets, not CFV slots.

Prefer a plan-owned mapping with a dedicated byte method, or a dedicated exact metadata-byte helper for a constructor-local mapping. Keep `GpuPlan::staging_bytes` meaning reach+CFV (`plan.rs:493–498`); silently putting metadata there would blur existing APIs. New bytes must enter both full-F32 selection and compact admission (`mod.rs:213–220`), not disappear into the 512MiB reserve. The immutable GPU slice is constructed/uploaded before graph capture, passed only to training up at `mod.rs:974`, remains outside seven swapped workspace arrays, and survives all graphs. Down/eval/chance retain original children.

For full child indexing, added GPU payload/upload is exactly `4 * tree.children.len()` plus one allocation. Host construction temporarily needs that many bytes and initialization/mapping work; a plan field may make that allocation earlier in the same timed constructor. The table includes chance/sentinel/unvisited positions, so visited-action edge counts are only a lower bound. Count retained versus temporary host memory correctly. Constructor cost is unmeasured and could erase solve savings, especially for river.
