# D033 independent API and placement review

Status: source/API feasibility review, before the builder's final protocol and before implementation. No GPU execution, build, profiler invocation, installation, privilege change or checkout edit by this reviewer.

The CUDA 12.6.3 Driver API supports timing-enabled events and explicit event-record graph nodes. Create events with `CU_EVENT_DEFAULT`, not `CU_EVENT_DISABLE_TIMING`. The capture alternative is `cuEventRecordWithFlags(..., CU_EVENT_RECORD_EXTERNAL)`; that flag is only valid during capture. Event timestamps are overwritten on subsequent records, so read a completed sample before replaying the same handles. Elapsed-time resolution is approximately 0.5 microseconds, and intervening device scheduling can affect the interval. These contracts support feasibility, not a runtime proof on the installed driver. [Event API](https://docs.nvidia.com/cuda/archive/12.6.3/cuda-driver-api/group__CUDA__EVENT.html).

`cuGraphAddEventRecordNode` records its event on each graph launch after its dependencies. Graph operations must be serialized. [Graph API](https://docs.nvidia.com/cuda/archive/12.6.3/cuda-driver-api/group__CUDA__GRAPH.html).

Local cudarc 0.19.7 source matters: `new_event(None)` disables timing; `CudaEvent::record` does not request an external record node. The raw APIs and borrowed `CudaGraph::cu_graph()` accessor are present. Borrowed original graph handles must never be destroyed by the diagnostic. Own only cloned graph/exec handles and the newly created events, retaining their owning context/stream and solver buffers until all work has completed.

The agreed placement is an owned clone of each actual E015 captured graph, with a strict kernel-only single-chain precondition. Inspect original nodes, edges, functions and launch dimensions. Preserve every original node, edge and kernel parameter; insert N+1 shared, ordered event boundaries. Each original predecessor precedes the inserted boundary, which precedes the original successor. Reject unexpected branches or node types instead of imposing a total order. Side-branch events with no successor dependency would not define reliable adjacent intervals. Inserting boundary nodes preserves original arithmetic and original-node order, but changes the executed graph and its scheduling overhead.

Keep the normal iteration increment, discount upload and p0-then-p1 order. Use independent identical solvers for ordinary and instrumented schedules. Compare raw device learning/reach bits as well as full compressed state and exploitability bits at fixed checkpoints; compressed equality alone can hide float differences. The baseline schedule must retain ordinary E015 graphs, not a second instrumented clone.

Within a batch, event handles may be reused if the output labels the extracted intervals as the final replay only. They are not batch averages. Synchronize after the whole batch, then extract timestamps before the next instrumented replay. Use identical outer event brackets for ordinary/instrumented batches to expose overhead; do not divide a single replay's node sum by a multi-replay envelope. Instantiate/create events and upload both graph sets before brackets. Keep all declared samples, including unstable or failed results; nonfinite or negative intervals invalidate the diagnostic, while sub-resolution zero intervals limit useful ranking.

The proposed anchor is a sealed native final iteration T. A warmup of T-60 must leave at least two ordinary iterations completed so both captured graphs exist. This is suitable for a rainbow fixture ending at T=200, if verified, but cannot be generalized unchanged to a T=60 river fixture. Final protocol values remain the builder's responsibility and must be sealed before execution.

All measurements are instrumented device diagnostics. They exclude construction, JIT/capture, event allocation and CPU readback from the reported node intervals, and therefore do not measure complete-cycle performance. Rankings can guide a bounded hypothesis; they do not establish native time shares, causal speedup, or acceptance of an optimization. Preserve the unchanged frozen evaluator and all failed evidence.
