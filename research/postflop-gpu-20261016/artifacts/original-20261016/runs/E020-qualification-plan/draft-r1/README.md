# E020 broader qualification preparation

These scripts are prepared outside the checkout and have not executed. The entry gate is the terminal qualifying primary report, its independent audit, reviewed E020 source and an independent review of these scripts. E020 remains unaccepted until broader checks, the separately frozen wide-turn holdout, fresh-original cumulative qualification and final independent audit all pass.

The fixed new run IDs are listed in protocol.json and were absent from both raw runs and dashboard when prepared. The scripts recheck absence before execution. Preparation does not reserve or create those native run directories.

Root creates authorization.json with candidate E020, primary_independent_pass, source_review_pass and qualification_script_review_pass all true, the exact prepared_manifest_sha256, and evidence_sha256 mapping absolute review/evidence paths to hashes. It must include the independent primary and script review evidence. Then run `python -B build.py <authorization SHA256>`. This serially builds gpu-feature state/menu/resume/GPU controls and preflop-research continuation controls under the GPU lock. It writes seven immutable executables/manifests and a terminal complete.json only after both Cargo jobs, source checks and binary copies succeed. It does not execute tests or replace the existing gpu-only primary binary. Build failures and owned-child cleanup stay under the lock.

Before any additional GPU controls/timing, root must also finish and freeze the independent holdout and resource probe binaries. Create all-builds-ready.json in this folder with all_required_builds_terminal, all_builds_terminal, holdout_builds_terminal and holdout_build_source_review_pass all true; broader_build_complete is {path,sha256} for runs/E020-qualification-build/complete.json. Its artifacts map includes absolute paths and SHA256 for all seven broader executable/manifest pairs and the E015-holdout, E020-holdout and E015-resource executable/manifest pairs, plus terminal build evidence. Each executable's adjacent .manifest.json must contain binary_sha256. No compile may overlap a GPU run or occur between cumulative pairs.

Run `python -B controls.py <authorization SHA256> <all-builds-ready SHA256>`. The unchanged registered runner is called directly inside the existing lock; it still owns cleanup, telemetry, raw logs, source provenance and dashboard rows. The nine native processes are fixed: state, menu, resume, GPU integration, original F32, candidate F32, paging, rejection, stored-state. Every process is bound to its immutable executable and build-time manifest before/after. Runtime checkout provenance is explicitly distinct from the historical original binary. Signals raise through the runner's cleanup while the lock remains held.

The three frozen snapshot suites compare every ordered field against V000-state-baseline, V000-menu-baseline and V000-resume-baseline-r, totaling160 snapshots. Their metrics objects must be empty. Six GPU integration tests must pass; these contain tolerance checks and are not called full bitwise original comparisons. Fresh original F32 uses baseline-complete.exe and must match preserved V004-f32-baseline; all3 candidate results then match every non-timing field, including full state/root vectors/config/exploit/stopping data. Only six duration fields are excluded.

Only three continuation tests run: paging_preserves_resident_trajectories_and_rejects_invalid_inputs; symmetric_continuation_rejects_unsupported_inputs_without_mutation; gpu::continuation::storage::device_tests::direct_gpu_storage_preserves_720_full_state_passes. Exact160 paging sweeps and720 unique successful stored passes/full arrays are required. The stored test's unique GTO_SSD_STUDY_DIR is recorded; it uses unlimited RAM and does not establish SSD-spill coverage. No rejected E016 invalidation test or full preflop program is resumed. These internal references share candidate up_show and prove representation/lifecycle consistency, supplemented by the immutable-original F32/snapshot oracles.

The fixed holdout protocol remains independent and unchanged. After broader and holdout passes plus independent audits, root creates qualification-ready.json: broader_pass, holdout_pass, independent_broader_review_pass and independent_holdout_review_pass true; all_builds_ready, broader_report and holdout_report are {path,sha256}; evidence_sha256 pins the independent audits. Both reports must have status pass, and the broader report must certify160/3/6/3. Then `python -B cumulative.py <authorization SHA256> <qualification-ready SHA256>` runs exactly B065/E020C1, E020C2/B066, B067/E020C3 against fresh original baseline-complete.exe, reusing the unchanged E020 primary executable. No exclusions/extensions/substitutions are allowed. All18 complete non-timing result objects must be equal. No feature-enabled control binary substitutes for either timing binary.

Finally `python -B assess.py <authorization SHA256>` applies the unchanged shared comparison implementation: >=2% sum-of-fixture-medians improvement and no median fixture slowdown>3% repeated in at least2of3 pairs. It uses physical primary ID E020R1 and its already-preserved exact patch alias. It can publish qualifying or rejected, never accepted or deployed. Independent terminal evidence audit remains required. No holdout score is merged with primary or cumulative measurements.

Every stage uses explicit UTF-8, unique output paths and source/binary pins. At least50GiB free plus4GiB output reservation is required; builds use a1800s timeout with10s progress. Existing runner behavior is retained for native jobs. Controls/holdout/cumulative failures preserve raw evidence and stop; these scripts never retry, overwrite or automatically accept. No new broad lifecycle/ABI harness is needed for the integer-only showdown cache and matching shared-size expressions.
