# E020 wide-turn holdout implementation

Implements the unchanged prospective protocol `33d4a047f67d1b23bd125cbfc8c31b564b6cf6a8417da768023beb8389c71510`, frozen before E020 primary measurements. Preparation is source-only; no build or GPU execution occurred here.

`evaluator.rs` is a one-case derivative of the frozen primary test. The fingerprint helpers and solve/readback timing body are mechanically identical. Only the fixed workload, bounded admission, labels and after-timing evidence differ. `fixture.json` is byte-identical to the prospective fixture. The test is ignored by default; its exact filter is `postflop_wide_turn_holdout`. The separately ignored `postflop_wide_turn_resources` test compiles/loads the exact two CUDA variants and queries only this holdout's 1,128/1,081 shape; it launches no kernel.

`workspaces/E015` and `workspaces/E020` contain isolated copies. All 162 primary provenance entries are mapped to their immutable build manifests; the only production differences are the approved `gpu/mod.rs` and `gpu/kernels.cu`. Each copied solver manifest has the same two external test-target declarations appended. The root Cargo.lock, release profile, dependency declarations and other source bytes are preserved. No external dependency is added. Additional copied examples/server manifests and static include files make Cargo resolution independent of the active checkout. The original primary executables are never replaced.

The runner has three one-shot phases. Root alone invokes them, under the existing GPU lock, after independent review:

1. `build` compiles/freeze-copies E015-holdout, E020-holdout and E015-resource into `build/binaries/`, each with a source/dependency/binary manifest. It uses a separate `build-holdout-e020` target directory, release/locked/offline Cargo, and1800-second fixed timeout per arm. No test is run.
2. `resource` requires all broader and holdout builds already terminal. It runs the no-launch resource test and writes `resource/report.json`.
3. `cohort` additionally pins that exact resource report. It executes B1,C1,C2,B2,B3,C3, each in a fresh process with a600-second timeout. Results and complete framed raw CPU stores stay under `cohort/<label>/`. `cohort/report.json` alone is the holdout decision: `status: pass` requires all six exact results/checks/states and no frozen repeatable-regression guard failure. It never accepts or deploys E020.

Use separate immutable authorization files for each phase. Build authorization intentionally omits `all_builds_ready`; it cannot exist yet. Resource authorization adds the hash of root's common `runs/E020-qualification-plan/all-builds-ready.json`. Cohort authorization is a new file adding the canonical resource report path/hash. Never edit an authorization after use. Each phase takes `--authorization <absolute path> --authorization-sha256 <SHA256>` and the same prepared-manifest identity. Templates are illustrative and deliberately contain placeholders, not permission to execute.

The common readiness file must have `all_required_builds_terminal`, `all_builds_terminal`, `holdout_builds_terminal` and `holdout_build_source_review_pass` true, and an `artifacts` map of absolute paths to SHA256. It includes all three holdout executable paths and adjacent manifests plus the broader outputs. The runner revalidates these pins before and after every resource/cohort child. Cohort also revalidates the canonical resource report every time. All source/evaluator/fixture pins are checked before/after builds and native children. Compiler/profile/wrapper overrides are refused and their absence check is recorded.

The GPU memory admission stays unchanged:4GiB free,2GiB constructor budget, bounded node/CPU metadata estimates. The evaluator additionally reads `cuCtxGetCurrent` and `cuMemGetInfo_v2` only after scoring while the existing solver context remains live. This reports measured device-wide residency, not a solver-only allocation; it creates no new context owner and adds no measured wait. The small admission count checks use existing Spot river tables, with no duplicate GpuPlan.

Raw state output has a16-byte magic, framed metadata and exactly four typed stores, preserving every quantized word and f32 scale bit without decoding. The runner validates metadata, order, types, counts, bounds and EOF, then compares every byte using1MiB buffers. Root strategy vectors remain in exact JSON. Host-only codec tests reject eight corrupt structures plus a changed payload word. During draft review, a literal magic-length mismatch (15 instead of16) was corrected before any native run; this failed draft judgment is preserved here and in codec-selftest/report.json.

Child stdout/stderr are file-backed, dashboard heartbeat is best-effort every10seconds, and signal/exception/timeout cleanup runs while the GPU lock is held. Only pre/post GPU telemetry is read; there is no telemetry polling during native timing. Original accepted gains, primary scores and deployment fields are unchanged. Operational failures stop with retained evidence and no retry in the same phase directory. A failed numerical/quality/performance outcome cannot trigger an extension or altered fixture.
