# D041 additive history check and byte bound

The original note/manifest remain unchanged. This supplement addresses the closed-work comparison before any diagnostic or candidate implementation. No native process, build, GPU or CPU-heavy timing was run.

**Different scope from closed work.** E011-zero-design/README.md concerns compact inactive **readback**: replace Store::write_f32's all-positive-zero float max/quantization by exact owned q/scale fills. It was stopped before implementation because only the two-tone readback group could benefit. D011-design/README.md instruments optional quantized-readback constructor descriptor/functions/allocations; its native D011 output is a try_new diagnostic, not the input-store zero proof. D012/stdout.log splits the enclosing constructor but still groups arena uploads. D013-isolated-summary/report.json compares E004/E010 filtered fixtures to diagnose constructor history, not scan/encoding primitives. D014-host-max-proof tested four-lane **float maxima followed by quantization** and rejected that isolated encoder; D015-host-sse41-proof/candidate.rs specializes unchanged encode_i16/u16 to SSE4.1. E012 and E013 integrate those readback encoders and fail their primary gates. Their preserved arena.rs can_upload_zeros functions are **byte-identical** to the current accepted function. Therefore those tests did not measure or change this input-side integer zero proof. The similarity is that both touch host memory; their isolated encoder gains cannot establish a zero-proof gain.

The recent E020 reference total is9773.6231ms, so2% is195.472462ms. If only q scanning changes and other work stays fixed, aggregate current scan time must exceed that threshold even for an impossible zero-cost replacement. That is equivalent to an aggregate logical q rate below13.9883GB/s; this is an algebraic screen, not a measured hardware rate. Even pretending the entire historical upload group were the scan would require a speedup greater than2.0144x; real residual allocation/memset/wait costs shrink the opportunity. Combining these historical/current values is illustrative only. The first next evidence should be a narrow current host split of scale check/q OR/device allocation plus existing wait, without added synchronization or moving work outside the complete cycle. A subthreshold scan measurement is a NO-GO, not a reason to relax the gate.

No code is proposed until that split demonstrates plausible savings of at least the full-cycle threshold. Integer OR regrouping would preserve the exact existing classification (all q bits zero, scales exactly+0, snapshot state unchanged); it would not permit skipping checks on iteration0 or reclassifying signed-zero/nonfinite data. No change to E022 or its fixed cohort follows from this note.
