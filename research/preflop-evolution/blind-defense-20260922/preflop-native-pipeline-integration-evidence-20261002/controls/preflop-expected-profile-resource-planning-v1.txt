Scope: measured file/receipt timing and resource arithmetic only. No new poker
export, training, workload, filesystem compression, hardlink, or historical-file
mutation was performed. All GB quantities below are decimal. This is not a
correctness, strategy-accuracy, convergence, or throughput qualification.

preflop-expected-profile-storage-options-analysis-v1.json in this staging folder.

Prospective storage qualification, before a larger profile

Prefer ordinary inherited NTFS compression on a NEW, declared S: research
directory. Microsoft documents transparent lossless reads and compact /C
directory inheritance. Current ntfs_research_storage_v1.py already uses this
pattern but hardcodes T:/GTOpen-research, so it cannot be reused unmodified for
S:. A separately pinned helper should accept only the declared new descendant,
refuse existing targets/redirected parents, confirm the compressed directory
attribute and nested-file inheritance, and retain all control artifacts.

Use a small NEW control namespace (e.g.1GB allocated,.5GB logical,15min) to
copy the predetermined samples plus a fixed software stdin/stdout fixture.
Compare ordinary file reads, full and chunked SHA, JSON parse, size, native
execution receipt verification before/after representation change, and actual
GetCompressedFileSizeW allocation. A genuine tiny owned software child can
qualify the same authenticated stdout/receipt path without poker exports/fits.
Keep receipt filenames, original raw SHA and semantic native-process provenance.
Measure write/read overhead, cancellation during active software output, and
zero-byte/incompressible files. No historical path may be a mutation target.

WOF is a later alternative for closed immutable new raw exports. compact /EXE
does not inherit to future files; XPRESS4K favors access speed, LZX compactness.
Qualify it in a separate NEW subtree with the same raw SHA/receipt controls,
known WOF reparse tag only, and explicit allocation/backing-stream accounting.
The old stable_file inventory admits WOF tag0x80000017, but that fact alone does
not prove a new accounting path is complete or authorize blanket reparse tags.
Ordinary inherited NTFS avoids an extra post-close conversion step initially.

Hardlinking exact new stdout/native.json pairs is another lossless option, after
stdout closes and authentication succeeds. Limit aliases to one NEW profile on
one volume, verify same file ID/size/SHA, keep both named artifact refs/receipts,
and never reopen either name for writing. Microsoft notes that writes through
one alias affect all aliases. Current global inventory sums each name's allocated
size and therefore double-counts hardlinks; require a new qualified unique-ID
counter across all declared roots before any hardlink budget credit. Until then
the conservative named allocation is the budget metric. Do not link source,
receipts, mutable status, or historical artifacts.

Full-five-depth representative profile proposal (not admitted or executed)

Fitted depths20,40,100,200,400; one complete joint cycle,169deals/context
(845 total),13subbatches/context (65total),K2/context (10boards),posterior64,
F4 per actor,512postflop reservoir slots/player/context,3 physical and2 board
CPU workers at1 thread each, existing CUDA fit sharing/production guards.
Keep exact current model/resource/native identities and independently declared
new source/recipe identities; do not change poker sampling or mathematics to
fit a budget. Refresh inventory and separately register this profile.

Static public/river-state counts are20:148/92;40:263/178;100:399/298;
200:455/346;400:515/402. Totals1780/1316 imply12.027x public and14.304x
river geometry versus20bb. A deliberately rough raw-storage proxy is18.065GB
with duplicate copies,9.641GB with qualified unique hardlinks. Naive5x would
predict6.395GB and ignores deeper public geometry. Actual visited histories,
native subtrees, policy generation and menus can invalidate linear scaling.
The timing proxy is roughly18-22min from the same geometry, with wide uncertainty;
retain an explicit1h deadline rather than treating this as a measured forecast.
Preserved river limits remain32 target keys/export,64,000,000 raw stdout bytes,
64KiB request and60s/export. Deeper histories/subtrees are unmeasured and may
stop the bounded attempt at those limits. Compression does not relax any raw
per-export limit; changed grouping/budgets require separate source/recipe
qualification and must never be an implicit increase.

After transparent compression software qualification, a useful bounded attempt
would separate a24GB logical artifact cap from a10GB allocated-file cap. A
nominal4.2GB monitored-output reserve (2board jobs at2GB each plus3river jobs at
64MB) and2GB filesystem/metadata margin gives16.2GB, leaving roughly4.42GB at
this snapshot before qualification/control artifacts. This is an initial budget
proposal, not sufficient final admission evidence. run_native polls stdout and
stderr limits about every.1s, so they are not strict filesystem quotas; the
bridge/query/trace executables also write directly to output-path arguments,
outside that stdout/stderr cap. Derive and qualify direct-file/polling-overshoot
bounds or add exact prospective sink controls before spending this reserve.
Refresh the real inventory. The allocated guard must poll during every native loop,
stop cooperative pools on breach and include all prospective files. A logical
cap by itself receives no compression credit. The existing20bb runner only
counts logical bytes and reserves MAX_BYTES at admission; a distinct prospective
runner/accounting contract is required, with software refusal controls, before
using this split. Output-cap overshoot reasoning must include concurrent native
jobs and final publication overhead. Success is not guaranteed within these
bounds; a stopped attempt retains all artifacts.

Stability: after one all-five checkpoint, independently restore it, compare the
complete cumulative states/model/reservoir/sampler RNG/source identities, and
retain source-only refusal/restart controls. Then refresh actual retained bytes
and runtime before separately admitting a second all-five cycle. The raw
hardlink proxy for two cycles19.282GB leaves too little room for metadata,
in-flight output and policy/geometry uncertainty; do not reserve two unmeasured
full cycles from the current20.6GB headroom. No accuracy claim follows from any
software/resource profile.
