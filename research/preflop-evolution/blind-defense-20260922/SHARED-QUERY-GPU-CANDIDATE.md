# Shared-query GPU candidate: not yet qualified

The shared CPU-array preparation now has a separate CUDA candidate and a
crossed-batch adapter. No live study or production module imports them.

`prepare_cuda_queries` takes one isolated copy of the batch, prepares its common
arrays once, and uploads those arrays once. The four candidate banks reuse the
same prepared tensors. Each bank still builds its own model-specific table
overrides and computes its own reach-weighted policy average.

The crossed-batch adapter calls the existing evaluator and asserts that common
preparation happens exactly once. Preparation time is included in the first
bank call's timing, so summing the four bank times does not hide its cost.
Transport generation, native evaluation, outcome validation and artifact
format remain in the original evaluator. Input tensors are read-only by
contract; callers must not mutate a prepared object during evaluation.

Static checks passed: the model-construction method and the complete inference,
ordered accumulation, normalization and output-checking statements have the
same AST as the existing versions. All 880 Python source files registered by
the live study still match their recorded hashes. These checks establish source
structure, not numerical equivalence or a performance improvement.
