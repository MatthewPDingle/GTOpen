Current common runner omissions and failure semantics

preflop_expected_native_execution_v1.py:101-108 observes stdout+stderr file sizes
only; the final check at118-119 and verify_native at175-185 use the same two
files. Receipt stdout/stderr includes authenticated raw hashes, paths and byte
counts, with actual Popen argv and owned Windows process handle/creation time.
The direct CLI files are subsequently hashed and validated by pipeline/worker
logic, but are absent from the process receipt's byte limit and output witness.

The .1s child wait is not a strict sampling period: guard() runs first and can
take longer. The profile whole-store guard samples every3s and can spend1.2s in
a CUDA quiescence probe. Termination/kill waits are also additional latency.
Thus stat polling can refuse a completed over-budget export or stop a live
writer, but cannot prove a fixed transient disk-overshoot bound for ordinary
unbounded regular-file writes. Failed oversized files are currently retained,
which is the correct preservation behavior, but requires a reserve beyond a
nominal success cap. Faster polling alone is not a complete solution.

Smallest complete prospective acceptance-bound change

Use a separately versioned/pinned native execution contract with an explicit
direct_outputs list of canonical path, exact argv destination index and required
output role. Keep the actual native executable and exact argv in Popen; do not
insert a helper executable, replace file arguments with '-' or claim a wrapper
PID is the native process. Preflight each destination as a new unique file in
the invocation folder, distinct from pinned inputs and stdio/receipt artifacts.

Count stdout+stderr+all declared direct files in one explicit aggregate logical
byte limit both during the loop and after the owned child is terminal. Record
declared output specs and final direct-file path,exists,bytes,SHA in the terminal
receipt. Record missing and partial outputs on failure, preserve every existing
partial file, and keep owned-process return code/timestamps/failure details.
Never delete, truncate, relaunch or reuse an incomplete export. Success requires
all required files and the aggregate bound; the matching verifier must require
the exact expected output spec and rehash each output, then coordinator and
whole-result validation must apply it before any reservoir insertion.

Add exactly the three declarations above to the current call sites. Generic
capture paths also cover board and river stdout/stderr. A versioned receipt is
needed because existing verify_native rejects extra success-receipt keys. Keep
the seven public result reference keys if useful; qualify the new receipt
method/schema rather than reinterpreting preserved v1 receipts. Input/native
source hashes, model/resource bindings, posterior64 and ordered ingestion do
not need to change. Output limits are explicit operational admission fields;
they must not silently become a different scientific budget or sampling rule.

All three missing pre-write checks require newly pinned prospective binaries
and byte-parity/refusal qualification. Existing binaries and historical receipts
cannot be relabeled as if these checks existed. A refusal should emit a small
diagnostic with intended byte size/limit and leave the raw output absent or
partial as actually observed. Do not write the rejected oversized vector just
to create a full raw failure artifact; retain the genuine failed receipt and
all bytes actually emitted/written. Pre-write length checks bound disk output,
not peak memory used to build or serialize a tree.

For a rigorous cap on arbitrary failure stdout/stderr, pre-write payload checks
are insufficient: a qualified bounded stream sink or a source-proved diagnostic
bound is also needed. A pipe capture keeps native argv and owned child identity,
but any capped/truncated failure capture must explicitly label the retained raw
prefix and overflow witness as incomplete, never pass success verification, and
retain every observed byte within its declared sink budget. Do not silently
truncate a full artifact or call an incomplete prefix complete evidence. If full
raw failed output is mandatory, source-specific pre-emission bounds must cover
every stderr path instead. No strict current overshoot number is certified here.

Concurrency and raw reserve

The coordinator exports queries while3 physical CPU workers and2 board workers
are active (pipeline collect at182-228): SIX native children can coexist. Each
physical worker runs bridge,trace,history and selected sequentially; it never
needs four simultaneous process reserves. Contexts collect sequentially. Queued
futures cannot write until running, although preceding completed exports remain
part of the already retained store total.

A small prospective envelope, requiring explicit admission/control qualification,
is64,000,000 aggregate bytes per query/bridge/trace/river invocation and the
existing2,000,000,000 aggregate bytes per board invocation. These are proposals,
not existing enforced direct-file caps or proven deeper-stack sufficiency.

2boards*2GB + (3physical+1coordinator)*64MB =4,256,000,000 raw active-native bytes.
The retained three river stdout/native.json duplicates add up to192,000,000,
giving4,448,000,000 nominal bytes of new native output and its raw copies.
Budget receipt/process sidecars, filesystem/publication metadata and polling or
bounded-sink overflow separately; do not apply an empirical compression ratio
as a guarantee for this reserve. Compression may leave a partial file or tail
uncompressed and does not change logical/per-export limits.

Transport process.json embeds decoded stderr. Without a separately proved
successful stderr bound, JSON escaping can expand a byte to6 characters and
the extra stdout copy plus stderr JSON can approach6*64MB per river invocation.
A conservative unqualified Python-copy envelope is therefore5,408,000,000 bytes
instead of4,448,000,000, plus fixed metadata and unproved polling overshoot. For
this exact successful pinned river producer the diagnostic shape is fixed and
small (measured maximum84bytes,process.json226bytes); the source's fixed modes,
node/query caps and byte fields can support a qualified small allowance. Do not
assume arbitrary new stderr follows that shape without a control/source pin.

If a future capture explicitly allows one64KiB retained overflow witness per
stream, six processes/twelve streams need another786,432 bytes, in addition to
their normal caps. That arithmetic is valid only for a qualified bounded sink;
it is not a substitute for bounding the three regular-file writers. Keep a
separate2GB metadata/publication reserve and refresh the global inventory before
any new admission. The separately reported NTFS809-file retention control does
not cure missing direct-file or transient byte accounting.

Essential prospective software controls, before a native workload

Each declared direct-output role: valid output,large direct file with empty
stdio,too-large stdout/stderr,combined-only overage,immediate child exit before
poll,missing/partial file,changed output path/hash/budget,owned-child cancellation,
and retained terminal failure. Verify authentic exact argv/PID/creation time,
receipt schema/all output hashes, failed evidence retention and zero reservoir
mutation. Include3physical+2board+1coordinator concurrency, largest measured
raw-file byte fixtures, NTFS inheritance, bounded sink overshoot if chosen,
and unchanged compact JSON/trailing-newline bytes for prospective Rust export
helpers. Those are software controls to be separately authorized and registered;
this read-only review has not run them or admitted a scientific profile.
