# Lossless storage control for the wider evaluation

23 September 2026. Completed-control files only; active training and production
were not changed. No active-candidate policies were inspected.

Creating a new NTFS-compressed parent makes new nested output files inherit
compression. A copied 466-deal evaluation retained every decoded byte, relative
path, length and last-write timestamp across 194 files. Its configurable scalar
readback passed again, including both chance streams, every class choice,
training-half stability, native payoff reconciliation and all five intervals.

The copied artifacts occupy about **65.5 MB**, versus **196.8 MB** logical size:
about one third. No custom archive reader or changed artifact format is needed.
The source files were verified unchanged. Copying and flushing took about two
seconds; the complete control including verification took 4.8 seconds. This is
not a full-run performance measurement.

## A preserved failed check

Version 1 measured allocation immediately after copying through Windows' file
cache. All compression attributes were set, but allocation had not yet fallen,
so its admission assertion failed. Read-only observations subsequently showed
allocation declining. That registration, source and store were preserved.

Version 2 flushes each completed file before measuring allocation. It passed;
there was no changed poker arithmetic or altered evidence. A future writer must
allow for buffered writes and guard actual free space throughout execution,
rather than assuming a compression ratio from attributes alone.

## Planning implication

Scaling this measured allocation to 174,336 planned deals, then adding a 50%
margin, gives approximately **36.8 GB**. The drive had **83.9 GB** free at the
measurement, so this estimate leaves the required 40 GB reserve intact.

This supports candidate-specific resource admission; it is not a guaranteed
bound. The control used four models and 16-deal batches. The intended complete
bank, batch size, query counts, serialized numeric values and execution speed
must still be measured. Register the final resource/sample budget before the
full run, and stop on actual reserve, deadline or integrity failures. Retain
all outcomes and do not reduce a planned test count after seeing its results.
