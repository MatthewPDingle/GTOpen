Run only after the currently registered matched continuation releases the GPU.
This control reuses the eight immutable parent-pilot reservoirs at boundary 80.
It does not draw evaluation deals, update a learning bank, or change production.
The previous CPU control passed exact 302-feature bytes across 1,558,846 rows.

For every parent arm and player, fit the original and vector implementations
with the original model-80 fit seed, 512 optimizer steps, 4,096-row chunks,
learning rate 0.003, float32 parameters, TF32 disabled and deterministic CUDA.
Alternate which implementation runs first across the eight fixtures. Preserve
the original source files and verify all frozen CPU-control input hashes.

Require both implementations to reproduce the saved original model-80 network
exactly. Require identical advantage scales, normalized objectives and every
non-timing fit metric, also against the saved original metrics. Record complete
fit time, setup, graph capture, optimizer time and peak allocated/reserved CUDA.
One pair per fixture is descriptive; it does not establish a general speedup.

Use the existing exclusive research lock and production-priority guard, permit
light desktop activity below 65% GPU utilization, cap own CUDA at 4 GB and keep
2 GB external headroom. No competing GPU control runs during the active study.
Limit the control to twenty minutes, preserving completed case records and
failure evidence. A failure requires an explicit versioned recovery; never
overwrite the original registration or treat a timeout as a completed control.
Only small JSON evidence is written under the research directory.

The runner's default mode verifies readiness without starting fits. Its --run
mode registers and executes only after idle/resource checks pass. A successful
result still requires complete-update/checkpoint equality before this runtime
is adopted in a future study. Neither timing nor parity implies better ranges.
