# Weighted source binding, root and table controls

Validate a complete 512-deal class-stratified generation against the original
game's blocker-adjusted class masses and physical range support. Bind each
32-deal native transport to its exact source slice and query digest. Accept all
512 source deals exactly once in a root update, even when batches arrive in a
different paired order. Keep integer sample counts separate from importance mass.

Use two updates with synthetic signed root targets to compare weighted sums with
a direct scalar calculation, and require exact checkpoint restore/continuation.
Reject detached weights, wrong physical cards, changed game identities, incomplete
or repeated source coverage and incompatible checkpoint formats without mutating
the accumulator. No real native traversal or model improvement is implied by
synthetic target audits.

For preflop tables, use 120 synthetic targets on twelve existing native catalog
observations, with enough storage to retain every visit. Compare weighted means
to direct per-visit arithmetic at 1e-12 tolerance. All-one weights must reproduce
the original table's scores and probabilities. Old and new public readers must
reject each other's formats; zero importance mass must be rejected.

Run single-threaded numerical code with at least 20GB free host memory and CPU
load below 70% at admission. Maximum 180 seconds; no GPU work, new poker solves,
application changes or large checkpoint writes. Full traversal ingestion,
training/model checkpoint integration and a bounded poker pilot remain required.
