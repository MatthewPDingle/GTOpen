# N19: practical strategy stability

This is a separately registered diagnostic, not another model or a relaxed
qualification gate. Run only after the selected N17 or full-precision N20 implementation passes its fresh accuracy, independent
GPU correctness, repeated speed and changed-policy checks. The qualified queue
must have exited (including N20's controller when selecting N20). Preserve the live app and all frozen models and sources.

Resume both ordinary and candidate iteration-500 saves from the changed-policy
study. Inspect both at 1,000 and 1,500 iterations, alternating arm order. Use the
same selected implementation and source game; no warm-up, refitting or changed
settings. Permit a start only with at least 90 minutes remaining. Check the
fixed research deadline and actual process ownership before every child.

Report cumulative GPU learning time, process/setup time separately, summed
frozen-value best-response gaps, aggregate action-frequency changes, and
reach/combo-weighted per-hand total-variation changes at every inspected node.
For weighting, average each hand's own reach in the two snapshots,
then multiply by its 6/4/12 pair/suited/offsuit combinations. This is a marginal
own-range diagnostic, not full joint reach or exploitability. Keep all inspected
nodes and also report maximum unweighted hand variation to expose rare hands.
A node with no arriving own-range mass has an unavailable weighted diagnostic
and cannot count as a passed stability signal; retain it in the report.

The prespecified practical-stability signal requires, in both consecutive
500-iteration intervals, at most one percentage point of aggregate action
frequency change and weighted per-hand total variation at every inspected node,
plus summed frozen-value gap <=0.005 bb at the interval endpoint. If either arm
misses it, report that it did not establish stability within this budget. No
threshold changes or selectively dropping branches. Even a pass only establishes
this limited signal: range-dependent continuation values, limited inspected
nodes and approximate multiway card removal prevent a full-game convergence
claim. Equal iteration counts are not equal solution quality.

Compare runtime to this signal only when both arms meet it; otherwise report
the measured trajectory and the unresolved performance question. Historical
150-to-500 work was run while generating the changed policies and may have
different system load; do not substitute its time for the isolated repeated
N17 benchmark. These extra saves still carry Balanced metadata and must never
be loaded in the ordinary app. This diagnostic does not qualify new ranges for
deployment or replace fresh reference checks at those ranges.
