# Shallow model integration and fresh-range test

This is an offline research study, not a deployed model. Production remains on
port 56708. The server and solver library were not changed.

The previous study's frozen correction is selected by passing this directory's
`interface.cu` to the standalone `learned_interface` executable in `candidate`
mode. Passing the old kernel selects the baseline. Passing `balanced` disables
learned pricing. This is an explicit research switch, not a new app setting.

## Read the results

- `CONCLUSIONS.md`: interpretation and next steps, written after all references.
- `REPORT.md`: integration, strategy, accuracy and timing results.
- `PROTOCOL.md`: thresholds and sample design fixed before solving.
- `implementation-freeze.json`: implementation, binaries and input hashes.
- `manifest.json`: new ranges, board sample, evaluator hashes and reference jobs.
- `status.json`: reference batch progress; `evaluation.json`: complete results.
- `probe-check.json`, `guard-check.json`, `*/audit/parity.json`: correctness checks.
- `tree-boundary-check.json`: native full-tree checks around the stack boundaries.
- `stability.json`, `policy-changes.json`, `timing.json`: policy and cost checks.
- `branch-diagnostic.json`: post-evaluation attribution of remaining decision error.

The model's 18 coefficients are unchanged. Below its SPR 0.2 training boundary,
the correction tapers to zero; between 0.75 and 1 it blends into the previous
model. These extensions are mathematical assumptions, not extra training data.

## Scope

Both preflop arms start fresh in the same 40bb heads-up game. The corrected arm's
3000-iteration ranges feed 150 reference solves: the same 50 stratified flops for
calling an open, calling a 3-bet, and calling a 4-bet. The comparison holds those
new ranges and future preflop choices fixed. It does not establish which entire
preflop policy earns more, nor validate first-in/limped branches, larger games,
different postflop menus, rake or arbitrary stack depths.

Research `policy.gtop` saves retain Balanced metadata even though an external
kernel supplied the values. **Do not load them in the app and interpret them as
ordinary Balanced solutions.** Their intended consumer is the offline driver.

## Reproduce or resume

From the repository root, use Python with NumPy and Torch installed and set
`OPENBLAS_NUM_THREADS=1`. This workspace uses `core.autocrlf=false`; older frozen
research inputs also require their original bytes. Build the probe separately:

```powershell
cargo build --release -p solver --example shallow_probe --features preflop-research --target-dir target/shallow-research
python tools/research/shallow_native_study.py probes
python tools/research/shallow_native_study.py parity
python tools/research/shallow_native_study.py guards
```

The recorded preflop driver is in
`target/learned-interface-filtered/release/examples/learned_interface.exe`; the
reference driver is `target/range-value-reference-night2.exe`. Exact executable
hashes are recorded rather than assuming a rebuild is byte-identical. NVRTC's
local path is supplied by the Python runner.

The study is already registered. `register` and `prepare` deliberately refuse to
overwrite registrations. Do not rerun preflop `solve` over the frozen results.
Resume missing reference jobs and evaluate them with:

```powershell
python tools/research/shallow_native_feedback.py run
python tools/research/evaluate_shallow_native_feedback.py
python tools/research/report_shallow_native_feedback.py
```

Each new GPU job requires the live app to be idle; only read-only status requests
are made. Completed reference jobs are validated and reused. Changed frozen
inputs, unmatched labels or failed accuracy targets stop the run.

Additional tree-boundary fixtures are generated by `shallow_boundary_seed` and
checked by `tools/research/shallow_tree_boundaries.py`. The seed example requires
`preflop-research`; both new Rust examples also compile with that feature disabled.
`dependency-audit.json` records that the imported action-audit helper and reference
driver source match the pre-study commit. It supplements the initial hash lists.
