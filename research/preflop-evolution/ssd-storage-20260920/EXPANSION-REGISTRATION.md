# Outcome-blind broader training registration

Purpose: broaden the connected two-player training board coverage while keeping the exact explicit GPU calculation and the original entering ranges, pot/stack/rake/tree settings. This is an intermediate accuracy study, not a production model or a substitute for flexible multiway validation.

Before any new strategic solve, construct candidate panels of 128, 112 and 96 canonical flops using systematic sampling proportional to physical orbit mass from all 1,755 canonical flops (22,100 physical flops). Use the fixed SHA256 offset seed `stored-expansion-full-population-20260920-v1`; preserve fixture order. Give each selected orbit equal total board weight because the sampling probabilities already incorporate orbit mass. Each continuation still averages every suit relabeling. Do not reject boards or move the offset based on strategies, features, costs or previous outcomes.

Use the verified CPU capacity audit to choose the largest candidate that satisfies ALL of: host retained payload plus canonical state <=72,000,000,000 bytes; predicted constructor GPU payload <=18,000,000,000 bytes; actual available host RAM >= planned host payload +6,000,000,000 temporary/overhead allowance +20,000,000,000 reserve; actual available GPU >= predicted constructor payload +3,000,000,000 reserve. Recheck live resources immediately before a strategic run. If none fits, retain the candidates and diagnose storage; do not silently shrink below 96 or alter the tree. Admission limits may be tightened for observed overhead, never loosened without a new recorded plan.

Freeze a fresh 95-board validation sample from the remaining canonical orbits, excluding the union of all candidate panels and all 164 previous comparison orbits. Use seed `stored-expansion-reserved95-20260920-v1` with the same physical-mass systematic sampler. This is independent validation of the remaining eligible population, not an unbiased full-deck metric. Record excluded/eligible physical mass and structural opportunity differences. Existing 164-board evaluation remains a known comparison panel; any training overlap must be reported.

The longer three-board 500-iteration resident/RAM exactness gate must pass before a broader strategic run. First run a short bounded pilot with the chosen panel to check actual memory, throughput, finite probabilities and conservation. Full learning and held-out transfer schedules require a separate frozen protocol informed only by resource cost and diagnostic validity, not cherry-picked strategic outcomes. Preserve all manifests and rejected capacity candidates. Training and validation generation must not read strategy result files.
