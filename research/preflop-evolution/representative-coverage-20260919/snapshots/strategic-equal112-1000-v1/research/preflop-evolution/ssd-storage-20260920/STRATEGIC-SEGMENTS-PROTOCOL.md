# Resumable 112-board strategic comparison

Prepared before the full-size seed finishes. No segment may launch until the seed's fresh-process restore passes and its measured-cost schedule has been reviewed and registered in `strategic-segments-v1-registration.json`. That registration records the schedule SHA-256 and exact runner/protocol/helper hashes. These are research validation gates, not a request for further user permission.

Preserve `STRATEGIC-COMPARISON-PLAN.md`: weighted 112-board training first, then the same 112 boards with equal weights, each to exactly 2,000 learning iterations. Save new, separate snapshots at 500, 1,000, 1,500 and 2,000. The weighted branch resumes its qualified iteration-20 seed. Equal-weight training starts fresh. Never carry learned state between the two branches. Keep all checkpoints and failed artifacts; no automatic overwrite, deletion, retry or deadline extension. Do not inspect new reserved-panel strategic outcomes before both final policies are frozen.

Use the qualified checkpoint executable, original subtree and two unchanged manifests. Verify source/runtime/input hashes before and after each segment. Before starting each GPU process, require production to be idle, the original audited host payload plus 26 GB available RAM, the audited device bound plus 3 GB available VRAM, and free SSD capacity for every remaining registered checkpoint plus a 100 GB reserve. Maintain the existing runtime guard's 20 GB RAM and 3 GB VRAM reserves. Stop only research if production becomes active. Per-sweep SSD strategy writes remain zero.

Register stage deadlines only after the full-size seed's save and restore succeed. The schedule uses twice the measured setup-plus-restore, save/teardown, slowest early training step times remaining iterations, and slowest evaluation times expected evaluations, plus 600 seconds, rounded up to five minutes. Reject any stage exceeding the guard's 12-hour ceiling. This is a conservative admission estimate, not a mature-speed guarantee. Any failure stops the chain for review.

Hash every predecessor snapshot file before use. Native import requires matching identity, shape, iteration, checksums and fixed weights; failure discards the process. At every resumed boundary, require scientific outputs to equal the previous segment's final outputs exactly. Validate all scientific checkpoints for finite normalized policies, terminal probability, chip/rake conservation and correct storage/transfer accounting. Validate the final snapshot's complete file set, identity, iteration, headers and byte budget; freeze file hashes and result hashes. Recheck predecessor hashes after the process exits. Fresh equal-weight training must start with iteration zero and no resume path.

Each successful segment is intermediate research evidence only. Record the final within-panel gap without changing the 2,000-iteration endpoint to obtain a favorable result. A gap above 0.01 bb at that endpoint is underconverged. Complete the separately specified reserved-panel comparison before claiming an accuracy improvement. No production deployment is part of this registration.
