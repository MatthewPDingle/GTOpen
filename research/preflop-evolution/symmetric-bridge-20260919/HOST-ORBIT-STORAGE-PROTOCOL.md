# Storage-only suit-orbit prototype

Registered 20 September 2026. The compact chance-traversal bridge has unresolved independent-trajectory differences. Investigate a different, exact storage path: retain full explicit GPU traversal with the existing symmetry-tied reference, but store only representative public-card branches while a board is parked on the host. This prototype must restore every bit; it does not relax the compact traversal gates or authorize production promotion.

Use the same three flop textures, two coherent reach schedules, hands, pot, stack, rake and no-raise 50% menu. Train the **explicit symmetry-tied GPU reference** for 300 iterations; the original schedule runs through 100 and is then held fixed. At iterations 1, 17, 100, 300, gather all four arrays' active canonical action blocks using the existing isomorphic plan, restore them into a fresh zeroed full solver, and materialize public-card siblings using the independent CPU materializer. Compare every original/restored float bit, including inactive storage. Register all 24 cases before seeing results.

If restoration is exact, run two ordinary full GPU passes from the original and restored states and require returned values and all four resulting arrays to match bitwise. No compressed chance traversal is involved in this check. Print every case, including mismatches, before final assertion. Record packed array bytes and local encode/restore timings; these are tiny fixture observations, not full-forest throughput estimates. Metadata, staging buffers and solver objects are excluded from the array-byte ratio and must be budgeted separately before larger work.

The prototype applies only to the explicitly symmetry-tied states and supported symmetric ranges. It does not prove lossless compression of arbitrary unprojected solver arrays, asymmetric locks, per-combo models or every future tree. No codec quantization and no change to the explicit solver's update rule. A pass would justify a separate paging integration with exact repeated-switch tests and host-capacity measurement; it would not establish that the 164-board forest fits or runs efficiently.

Test: `crates/solver/tests/continuation_host_orbit_storage.rs`. Two build workers, sequential execution after current jobs, production-idle checks, source/executable hashes and resource guard. Maximum execution 15 minutes, capped at 09:00 Adelaide.
